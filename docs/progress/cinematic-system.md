# Autonomous cinematic system progress

Last updated: 2026-09-01

## Architecture map

```text
campaign.yaml + references
  ├─ existing: storyboard.json → Remotion timeline
  │                           ├─ React 2D layers
  │                           └─ PixiJS deterministic particles/VFX
  │                              → FFmpeg delivery/inspection/verification
  └─ new: production-plan.yaml
            → shared asset search
            → asset-manifest.yaml (reuse | adapt | create)
            → procedural geometry + motion factories
            → immutable verified assets
            → executable 3D scene contract
            → Blender scene backend + semantic evidence
            → generic frame-exact edit plan + deterministic soundtrack
            → verified FFmpeg delivery
```

The application layer remains the reusable operation boundary. The CLI is thin. Generative providers may create persisted inputs, but deterministic rendering and verification remain provider-free.

The reference benchmark is a demanding acceptance fixture, not the product boundary. Work discovered there is promoted only through renderer-independent contracts, generic policies and verification, backend adapters, and regression tests; benchmark IDs, shot names, edit order, and hand-tuned coordinates are not reusable architecture. A completed render is not evidence that the human-performance or visual-fidelity stack is mature. As of 2026-09-01, architecture and campaign automation are substantially mature, while naturalistic animation, character fidelity, world richness, and overall cinematic finish remain active quality blockers.

## 2026-09-01 production-value priority steer

Naturalistic gait remains rejected, but it is deliberately parked rather than treated as the highest-value use of the current iteration budget. The full MPFB/Rigify production rig remains the intended render/deformation backend; the reduced canonical skeleton remains the portable motion, interaction, compatibility, and retargeting contract, not a lower-quality production substitute. The failed v23 lateral-support attempt is retained as rejected evidence and must not be described as completion.

The active priority is reusable production-world capability: environment silhouette and modular dressing, physically legible materials, lighting rigs, portable world assets, hair/fluid/particle/VFX layers, and sound effects. Work must produce general asset contracts, verification fixtures, and library candidates usable across campaigns; the reference-city shot is only the first conformance consumer. Motion returns when a shot requires it or after the higher-leverage world/appearance stack has materially advanced. This explicitly protects time and iteration budget for production-quality lighting rigs, textures, portable models, inhabited environments, hair/fluid/particle/VFX layers, and sound rather than repeatedly polishing one rejected walk.

The steer was reaffirmed after the gait/rig diagnosis: locomotion is under a hard default freeze, not merely deprioritised informally. Known backward travel, leg/foot ordering, hand deformation and toe-deformation concerns remain recorded rejection evidence. They do not authorise another motion iteration unless a concrete production shot is blocked or a reusable asset requires a deformation probe.

This is also an explicit allocation rule, not merely a note about sequence. Do not keep spending iteration budget polishing the rejected benchmark walk while a world-building subsystem can create a reusable production asset or capability. The existing motion evidence is sufficient to preserve the known defects and requirements. Resume character-motion implementation only when it blocks a concrete shot, when a reusable production asset needs an animated deformation test, or after the world, appearance, VFX, and sound layers have materially advanced. A static stand-in, architectural witness, product proxy, or accepted existing performance may be used to verify those other domains; this does not lower their production-quality bar or turn a proxy into a final character.

Investment order is now explicit: (1) modular environments and portable set dressing that create depth, scale, habitation, and cross-campaign reuse; (2) physically legible material and texture families plus reusable lighting/practical rigs; (3) atmospheric, particle, fluid, compositing, and secondary-light layers; (4) isolated, searchable sound-effect inventory and deterministic mix integration; (5) modular hair and other character-adjacent secondary simulation when demanded by shot distance. Locomotion polish is outside this sequence unless it blocks a concrete production shot. Each tranche must end in a renderer-independent contract, verification fixture, provenance-bearing library candidate, and at least one unrelated transfer—not a benchmark-only patch.

The user explicitly reaffirmed that it is acceptable to return to character motion near the end of this production-world expansion. Therefore completing one environment or one VFX experiment does not automatically reactivate locomotion. Before reconsidering the walk, the library should have credible reusable breadth across lighting rigs, surface/material families, portable models and inhabited set dressing, environmental and compositing VFX, isolated sound effects, and the hair/secondary-simulation capability actually required by intended shots. A high-quality full production rig remains available for final character shots; parking gait work is a scheduling decision, not a decision to ship a reduced-quality character or abandon the recorded deformation defects.

Next highest-value work remains production-world breadth: expand reusable lighting/practical rig inventory and verify it across unrelated environment families, then continue material/environment richness, portable models, physical VFX/compositing layers and isolated sound integration. Locomotion remains frozen under the exceptions above.

## AAA-inspired production-character pipeline assessment

The governing caution is preserved in [`docs/steering/aaa-inspired-character-production-pipeline.md`](../steering/aaa-inspired-character-production-pipeline.md). The current system is already converging on that architecture and must be evolved in place; a parallel `HumanPipeline2` would duplicate working geometry, skeleton, motion, interaction, clothing, material, renderer, verification, and library contracts.

The current humanoids have three distinct roles:

1. `createHumanoidMannequin` is the **proxy / motion-test body**. Its stable 22-joint core, continuous dimensions, attachments, and cheap geometry remain useful for gait, IK, interaction, camera, collision, and compatibility fixtures. It is permanently ineligible for production-character acceptance.
2. `createProductionHuman` is the **production foundation under construction**. Its continuous implicit body proves manifold anatomy, extremity ownership, generated skin weights, preserve-volume deformation, articulated hands, and renderer-independent inspection. The implicit body volume is an intermediate structural bridge, not the final visual topology and not a reason to polish primitives indefinitely.
3. `createProductionTemplateHuman` is the **stable-topology production-base experiment**. It converts the pinned CC0 MakeHuman hm08 mesh and authored weights into Videoer's existing geometry, 52-joint canonical skeleton, dual-quaternion skinning, attachment, motion, and verification contracts. It is an evolution of the existing architecture, not a parallel character system, and remains `validated`/visually rejected until its deformation, identity, materials, hair, clothing, and motion probes are accepted.
4. A **production character instance** will reuse that stable base topology plus body/face morphs, canonical weights, materials, modular hair, modular wardrobe, accessories, and compatible motion. The current template proves the topology/weight route but does not yet provide the complete morph or appearance stack.

Already implemented:

- a project-owned, renderer-independent character/mesh/morph/material/attachment contract and immutable library lifecycle;
- a stable 22-joint canonical retargeting skeleton, extended without renaming the core by 30 finger joints;
- continuous body dimensions and eleven continuous face-identity parameters;
- deterministic normalized anatomical-chain skinning, declared dual-quaternion/preserve-volume deformation, and measured joint-zone ownership/blending;
- renderer-independent facial expression morphs and renderer-consumable pose-space clothing correctives;
- modular fitted clothing, reusable material domains, layered base/additive/override motion, proportion-aware gait retargeting, analytic IK, gaze, and phase-based prop interactions;
- hash-bound structural and qualitative verification, including canonical body views, raised-arm/bent-elbow/bent-knee mechanics, bilateral hand rest/flexion, neutral/expression face views, walk, turn, and reach evidence;
- reuse/adapt/create resolution and fail-closed publication for accepted characters, garments, materials, motions, and derived performances.
- a pinned CC0 stable human template, authored-weight reduction into the unchanged canonical skeleton, profiled proxy-to-A-pose rest retargeting, geometry-derived facing/travel verification, final-skinned-surface grounding, and walk deformation gates for shoulders, hands, feet, and toes.

Partially implemented:

- reusable production topology: the pinned CC0 template now supplies stable body, face, hand, and foot indices, but it is not yet accepted, morph-complete, or published as a production base;
- reusable skin weights: authored source weights now map deterministically to the canonical skeleton and pass the current walking extremity gate, but joint-specific raised-arm/elbow/hip/knee correctives and full pose-suite acceptance remain incomplete;
- morph strategy: identity parameters and facial/expression targets exist, but stable-topology body morphs and joint-specific body correctives do not;
- modular hair: the domain/library policy requires separation, but the current crude scalp mass is still emitted inside the unfinished production-human generator and is not an accepted reusable hair asset;
- reusable character materials: material assets and procedural shading contracts exist, but layered skin response, normal/microdetail, and production eye/hair shading remain immature;
- verification: the core structural and motion set exists, but profile face evidence, an explicit rendered A-pose comparison, joint-specific visual deformation probes, clothed production-human probes, and shot-distance quality tiers remain incomplete.
- mature OSS production-rig integration: the pinned MPFB/Rigify backend now installs reproducibly, generates against the byte-identical hm08 mesh, exposes a typed profile-owned coordinate conversion, renders the same persisted walk, drives generated Rigify leg IK, and verifies anatomical heel/forefoot, lateral-sole, finger-flexion, and thumb-opposition evidence. Adapter v22 passes direction, elbow preservation, support-foot, toe-off, swing clearance, grounding, walking-base width, anatomical side order, pelvis-over-support, four-finger transfer, and thumb-opposition gates. The backend remains experimental because the shared motion still fails whole-body visual review.

Missing:

- accepted stable production topology and morph inventory for the body, shoulders, elbows, wrists, hips, knees, eyes, mouth, nose, and jaw as one coherent deformation-oriented base;
- accepted anatomical hands, face, ears, eyelids, oral cavity, hair, skin shading, and joint contours;
- reusable pose-space body correctives for shoulders, elbows, hips, and knees;
- an evidence-backed A-pose versus T-pose decision;
- explicit background/medium/hero/close-up quality classes with enforceable geometry, material, deformation, and evidence requirements;
- production-quality visual acceptance for any project-owned human asset.

Current largest visual blocker within the character subsystem:

Photorealism remains an explicit failed quality dimension. The current environment is improved relative to the original benchmark in cool/warm lighting separation, wet-surface response, architectural modules and reusable dressing, but it is not close to a photographic old-city street or inhabited bookshop.
