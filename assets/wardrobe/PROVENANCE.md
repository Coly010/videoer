# MakeHuman CC0 clothes packs

This directory records the licence/clearance evidence for six community
MakeHuman clothes packs fitted to the hm08 production base (ADR 023's
licensing-dependency policy). It does not contain the ~240 MB of meshes and
textures themselves — those are a git-ignored, hash-verified download, never
committed (see "Where the asset payload lives" below).

- Upstream: MakeHuman Community asset packs, `https://files.makehumancommunity.org/asset_packs/<pack>/<pack>_cc0.zip`
- Mirror: `https://files2.makehumancommunity.org/asset_packs/<pack>/<pack>_cc0.zip`
- Downloaded: 2026-09-03
- Basemesh: hm08 (same production base as `assets/character-bases/makehuman-hm08`)
- Record: `makehuman-cc0-clothes-packs-v1.json`, generated by
  `scripts/blender/mhclo_asset_manifest.py`

## Clearance rule

Every asset carries two independent licence signals: the pack manifest's
`license` field (`CC0` or `CC-BY`) and the `.mhclo` file's own header
comments. The header licence is normally read from an explicit `# license
...` key; when that key is absent, the scanner falls back to scanning the
header comments for a free-form licence mention (some assets' only header
line is an author signature like `# Cortu Johnstone - CC0`) before treating
the header as truly silent.

The header licence detection is three-way, not a plain "found it or not":

- **no licence line** — nothing in the header names a licence at all
  (true silence); clearance defers entirely to the pack manifest.
- **recognised** — the (explicit-key or free-form) text maps to an SPDX id.
- **unrecognised** — an explicit `# license ...` key is present but its value
  doesn't map to anything the scanner knows (e.g. `MIT`, `All rights
  reserved`, `proprietary - do not redistribute`). This is never treated as
  silence: the raw text is always preserved in
  `licence.mhcloHeaderLicenceRaw`, and it is forced into the same
  most-restrictive tier as AGPL/GPL, producing `commercialUse: unknown`,
  `clearance: rejected`, `agreement: conflict` whenever the manifest claims
  otherwise.

`scripts/blender/mhclo_asset_manifest.py` also recognises Creative Commons
modifiers (`NC`, `ND`, `SA`, any spelling/order/version, e.g. `CC-BY-NC
4.0`, `CC BY-NC-SA 4.0`, `CC-BY-SA 3.0`) and emits the matching SPDX id
(`CC-BY-NC-SA-4.0`, `CC-BY-SA-3.0`, ...) and creativecommons.org URL,
defaulting to version 4.0 only when none is stated.

On disagreement between the manifest and the header, the scanner adopts the
**more restrictive** of the two:

```
CC0 < CC-BY < CC-BY-SA / CC-BY-ND < CC-BY-NC* < AGPL/GPL/unrecognised
```

True header silence (not "unrecognised") is not treated as a conflict;
clearance simply follows whichever side does declare a licence.

- `CC0-1.0` → `commercialUse: allowed`, no attribution, `clearance: approved`.
- `CC-BY-*` (no modifiers) → `commercialUse: allowed`, attribution required,
  `clearance: review-required`.
- `CC-BY-SA-*` / `CC-BY-ND-*` (share-alike or no-derivatives, no NC) →
  `commercialUse: allowed`, attribution required, `clearance:
  review-required`; `licence.shareAlike`/`licence.noDerivatives` record which
  modifier applies.
- `CC-BY-NC*` (any NonCommercial variant) → `commercialUse: restricted`
  (never `allowed`), attribution required, `clearance: rejected`.
- AGPL/GPL/unrecognised/no licence on both sides → `commercialUse: unknown`,
  `clearance: rejected`.

Automatic production resolution may only select `clearance: approved` assets,
per ADR 023; `review-required` and `rejected` assets are quarantined pending
manual licence review and must not be pulled in automatically. None of the 64
assets across these six packs currently carry an NC/ND/SA modifier or an
unrecognised header licence — every `rejected` asset here is quarantined on
AGPL grounds — but the scanner handles them correctly should a future pack
include one.

## Current result (64 assets)

- **56 approved** (CC0 on both sides — this includes all four `cortu_*`
  assets: their only header line is an informal author signature, `# Cortu
  Johnstone - CC0`, with no machine-readable `# license` key, but the
  free-form licence fallback still reads `CC0` from it, agreeing with the
  pack manifest's CC0).
- **1 review-required**: `culturalibre_heroine_boots_4` — the pack manifest
  declares `CC-BY`, but its `.mhclo` header declares `CC-0`. The more
  restrictive CC-BY governs, so this asset needs an attribution decision
  before automatic use.
- **7 rejected** (quarantined): every asset whose `.mhclo` header declares
  `AGPL3`, regardless of what its pack manifest says, since AGPL is more
  restrictive than the manifest's CC0 claim and is incompatible with
  commercial, attribution-free reuse:
  - `frankyaye_mini_skirt_01`
  - `frankyaye_mini_skirt_02`
  - `skalldyrssuppe_tube_top_funky_colors`
  - `scailman_semitransparent_water_boots`
  - `scailman_gogo_platform_boots`
  - `grinsegold_female_pirate_boots`
  - `wdg_mycenaean_tunic`

The scanner's `verts`-block parser recognises both MakeClothes row shapes —
the 9-field weighted correspondence (`v1 v2 v3 w1 w2 w3 dx dy dz`) and the
single-index shorthand (a bare vertex index: exact 1:1 match, weight 1, zero
offset), matching MPFB's own `entities/clothes/mhclo.py`. Every one of the 64
assets, including `wdg_mycenaean_tunic` (whose `verts` block happens to open
with a shorthand row), now parses its full body-vertex correspondence set;
`parseWarnings` is only non-empty where a `.mhmat` texture key names a file
that genuinely isn't present in the pack (e.g. a typo'd filename), which the
scanner records rather than treating as fatal.

## Regenerate / verify

```bash
# Regenerate the committed record from a freshly extracted asset root:
python3 scripts/blender/mhclo_asset_manifest.py <asset-root> \
  --write assets/wardrobe/makehuman-cc0-clothes-packs-v1.json

# Verify a root matches the committed record (drift gate; used by the installer):
python3 scripts/blender/mhclo_asset_manifest.py <asset-root> \
  --check assets/wardrobe/makehuman-cc0-clothes-packs-v1.json
```

`--check` exits **1** and lists every differing asset/field (as
`MHCLO_MANIFEST_DRIFT ...` lines) on drift. Any hard error — a missing root,
no `packs/` directory, an unreadable or corrupt file — exits **2** with a
plain `error: ...` message on stderr instead, so the installer's drift gate
can tell "the packs disagree with the record" apart from "something is
actually broken" and react accordingly. The
record's `generatedFromRoot` is a fixed canonical label
(`work/sources/makehuman-cc0-clothes-packs-v1`), not the literal path passed
on the command line, so the same content produces a byte-identical record
regardless of where it was scanned from.

## Where the asset payload lives

`scripts/install-makehuman-clothes-packs.sh` downloads, hash-verifies, and
extracts the six pinned pack zips into
`${VIDEOER_MH_CLOTHES_ROOT:-work/sources/makehuman-cc0-clothes-packs-v1}`,
then runs the scanner's `--check` drift gate against this committed record.
`/work/` is git-ignored; the ~240 MB of meshes and textures is never
committed. Only this directory's two files — the record and this document —
and the two scripts are tracked in git.
