# Beacon One product conformance campaign

This is a deliberately different transfer test for Videoer's cinematic production system. It is a non-narrative product launch for an original, project-owned procedural emergency beacon. It does not reuse the reference benchmark's character, setting, interactions, editorial copy, or eight-shot story grammar.

```bash
npm run video -- cinematic-campaign validate campaigns/beacon-one-product-conformance/cinematic-campaign.yaml
npm run video -- cinematic-campaign build campaigns/beacon-one-product-conformance/cinematic-campaign.yaml
```

The operation builds the product geometry, semantic camera attachments, transparent editorial overlay, provider-free soundtrack treatment, three executable scenes, semantic render evidence, frame-exact edit plan, and verified nine-second delivery entirely from `cinematic-campaign.yaml`. Its `cinematic-audio-treatment-v1` source derives `audio.beacon-one-product-pulse@1.0.0` from a verified parent score, preserves temporal structure, and adds exact-sample interface/brand accents whose contribution is measured independently. Approval re-renders the treatment from the immutable parent before publication. Blender requires host Metal/GPU permission on sandboxed macOS runs.

The campaign exists to reveal accidental benchmark coupling. Its first run found that overlay scenes produced a composited final clip while generic edit assembly still selected the base clip unless a campaign manually special-cased the filename. That defect is now fixed through canonical scene-delivery selection and a regression test.

See `declarative-build-report.json` for the generated outputs and the explicit zero-bespoke-orchestrator result. The campaign remains creative data, while reusable code owns interpretation, validation, rendering, and verification.

The unrelated Last Platform campaign resolves the published nine-second treatment as direct reuse with zero audio adaptation, proving that the asset and derivation mechanics are not product-campaign special cases.
